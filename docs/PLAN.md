# 局域网聊天 / 传文件工具 — 规划与里程碑

> 版本：v1.0 草案 · 日期：2026-10-08 · 状态：待评审
> 技术栈：Flutter 3.32.8（UI）+ Rust 1.95（核心）+ flutter_rust_bridge 2.8.0（桥接）
> 目标平台：**Android 8+ / Windows 10+**（v1 不做 iOS / Linux / macOS）

---

## 1. 产品定义

### 1.1 一句话
同一局域网内的 Android 手机与 Windows 电脑自动发现彼此，配对成为联系人后，可像微信一样互发文字、图片和任意文件。

### 1.2 核心场景
1. 手机与电脑连同一 Wi-Fi → 打开 App 自动发现对方设备
2. 点击「配对」→ 双方确认（PIN 码/一键确认）→ 成为联系人
3. 进入聊天界面发文字/文件 → 实时送达、进度可见、历史本地保存

### 1.3 v1 范围
| 做 | 不做（v1 明确排除） |
|----|--------------------|
| UDP 局域网发现 + 心跳在线状态 | 互联网/云中继、账号系统 |
| 1v1 配对 + 联系人列表 | 群聊、语音、视频、朋友圈 |
| 文字、图片、任意文件消息 | 端到端加密（v2 计划，见 §6-15） |
| 断点续传 + 完整性校验 | 锁屏后台持续传输（v1.1） |
| 本地历史（SQLite）+ 未读角标 | 消息撤回/已读回执（v1.1） |
| 明暗主题、自适应布局 | iOS（工具链另算成本） |

## 2. 页面地图与用户旅程

```
启动页（权限检查/后台服务状态）
 └─ 设备发现页  [雷达动画 · 设备卡片列表 · 手动输入 IP 兜底]
     └─ 配对确认页 [6位PIN大字对照 · 倒计时60s · 确认/取消]
         └─ 联系人列表页（主界面）
             ├─ 搜索框（本地过滤）
             └─ 聊天页  [微信式气泡会话]
                 ├─ 输入栏（文本 + 「+」文件/图片）
                 ├─ 文件消息卡片（进度/状态/点击查看）
                 └─ 图片消息（缩略图 → 全屏预览）
设置页（主题、收件箱目录、发现方式、关于）
```

**导航策略**
- Android：单栏 + Navigator 栈（聊天页 push 进入，返回键逐级出栈）
- Windows：≥800dp 双栏（左 300px 联系人 + 右聊天面板，微信桌面式），聊天页不离开主框架

## 3. UI / 交互重点 ⭐

> 原则：**聊天体验的细节决定成败** —— 用户会拿它直接对标微信。

### 3.1 全局
- Material 3 `ColorScheme.fromSeed`，跟随系统 + 手动切换明暗（沿用现主题架构）
- 断点自适应：`LayoutBuilder` ≥800dp 双栏 / <800dp 单栏
- 所有空状态、错误状态都要有「插画/图标 + 一句解释 + 行动按钮」
- 时钟显示：列表相对时间（`刚刚 / 5分钟前 / 昨天 / 10-07`），聊天内绝对时间分组

### 3.2 设备发现页
- 顶部雷达/脉冲动画（发现中），停止发现后转静态
- 设备卡片：色块头像（首字母）+ 设备名 + IP + 平台图标 +「配对」按钮
- **手动输入 `IP:端口` 兜底入口**（应对 AP 隔离，见风险 §6-2）
- Android 首次进入：通知权限询问的引导卡片（不弹系统框前先解释用途）

### 3.3 配对确认页
- 双方各自显示 **6 位 PIN**（大字号、分隔符、可读性强），确认一致后点「确认配对」
- 60s 倒计时，超时自动返回发现页
- 设置里提供「跳过 PIN 一键确认」开关（便利与安全的取舍）

### 3.4 联系人列表页（对标微信首页）
- 顶部搜索框（本地实时过滤设备名/最后消息）
- 会话行：头像 + 名称 + 最后消息摘要（单行省略）+ 右上时间 + **未读红点角标** + 在线绿点
- 长按菜单：置顶（v1.1）/ 清空本地记录 / 删除联系人
- 空状态：「暂无联系人，去发现设备」+ 跳转按钮

### 3.5 聊天页（重点中的重点）
| 交互 | 实现要点 | 优先级 |
|------|---------|--------|
| 气泡布局 | 左右对齐 + 双方头像 + 圆角 12 + 深浅主题配色 | P0 |
| 反转列表 | `ListView(reverse: true)` 天然吸底，新消息零滚动代码 | P0 |
| 时间分隔线 | 相邻消息 >5 分钟插入时间胶囊 | P0 |
| 发送状态标记 | 发送中 spinner → ✓ 已发出 → ✓✓ 已送达；失败红叹号点击重试 | P0 |
| 输入栏 | 自适应键盘；**Windows：Enter 发送 / Shift+Enter 换行**；Android：发送钮 | P0 |
| 「+」菜单 | 发文件 / 发图片（图片先压缩出缩略图再发） | P0 |
| 文件消息卡片 | 图标+文件名+大小+**内嵌进度条**+状态；点击=打开/另存为/查看所在位置 | P0 |
| 图片消息 | 缩略图 + 骨架加载 → 点击 Hero 全屏预览（可缩放） | P1 |
| 文本长按 | 复制 / 重发 / 删除（本地） | P1 |
| 上滑查看历史 | 用户上滑时不强制吸底，显示「新消息」悬浮按钮 | P1 |
| Windows 拖拽 | 直接把文件拖进窗口发送 | P2 |
| 粘贴发送 | Ctrl+V 粘贴图片/文件 | P1 |

### 3.6 性能红线（UI 不许踩）
1. **进度事件节流 ≥100ms**，且只更新目标气泡（局部 setState / 独立 InheritedWidget），禁止整页 rebuild
2. 消息列表必须虚拟化（`ListView.builder`），500+ 条历史滚动不掉帧
3. 图片缩略图本地缓存，不重复解码
4. Rust 侧分块 IO（256KB/块）+ 流式哈希，**任何文件都不整包读入内存**
5. frb 事件流是推送不是轮询；断连时 UI 要有明确的重连状态条

## 4. 技术架构

```
┌──────── Flutter UI（Android / Windows 同一套）─────────┐
│ 发现页 / 配对页 / 联系人 / 聊天 / 设置                  │
│          ↑ Stream(消息·进度·在线状态) ↓ 命令调用         │
├──────────── flutter_rust_bridge 2.8.0 ───────────────┤
│ Rust core（独立 crate，可复用、可单测）                 │
│  discovery  UDP 组播 HELLO + 心跳 + 手动直连             │
│  pairing    握手 + PIN 校验 + 配对表持久化               │
│  session    TCP 连接管理 + 重连退避                     │
│  protocol   帧编解码 + 消息类型 + 版本协商               │
│  transfer   分块传输 + 断点续传 + blake3 校验            │
│  storage    SQLite（历史消息/联系人/未读游标）           │
└──────────────────────────────────────────────────────┘
```

**协议草案（v1，JSON payload + 二进制帧头）**

```
帧头:  magic "LCHT"(4B) | version(1B) | type(1B) | length(4B, LE) | payload
type:  0x01 HELLO / 0x02 HELLO_ACK   0x10 PAIR_REQ / 0x11 PAIR_RESP
       0x20 TEXT                     0x30 FILE_META / 0x31 FILE_CHUNK
       0x32 FILE_ACK(含offset续传点)  0x33 FILE_DONE(hash)
       0x40 PING / 0x41 PONG         0x7F BYE
```

- 会话内消息带 `(sender_id, seq)` 单调序号，**排序不依赖双方墙钟**（风险 §6-11）
- 收件目录：Windows → `文档/LanChat/`（可改）；Android → 应用私有目录（**零存储权限**，v1.1 再提供"保存到下载"）

## 5. 里程碑

> 预估按全职单人计；每阶段结束都有**双平台可运行的验收物**，避免最后才集成。

| # | 名称 | 目标 | 预估 | 关键交付 / 验收标准 |
|---|------|------|------|-------------------|
| **M0** | 工程地基 | 打通 Android 构建链与 frb 桥接 | 2d | ① `flutter build apk` + `flutter build windows` 都能出包并启动；② Rust 一个示例函数在**双端**都调用成功；③ UI 壳含 5 个占位页 + 自适应布局跑通 |
| **M1** | 设备发现 | 同网段互见 + 在线状态 | 2–3d | 双 Windows、Win↔Android 互见（设备卡片含名字/IP）；心跳 3s，离线 10s 内从列表消失；**手动 IP 直连兜底可用** |
| **M2** | 握手配对 | 成为联系人 | 2d | PIN 流程双向确认；配对结果持久化（重启免配对）；配对页倒计时/失败重试可用 |
| **M3** | 文字聊天 | 微信式会话 P0 集全 | 4–5d | 气泡/时间分隔/状态标记/输入栏/反转列表/长按复制全部可用；历史入库重启不丢；**500 条消息滚动无卡顿**；双平台键盘行为正确 |
| **M4** | 文件传输 | 大文件可靠送达 | 4–6d | 1GB 文件双向互传成功且内存平稳（峰值 <150MB）；传输中杀进程重启可**断点续传**；blake3 校验一致；进度实时反映；取消/失败有重试 |
| **M5** | 体验打磨 | 接近微信的完成度 | 3–4d | 图片消息+全屏预览；未读角标与吸底/上滑逻辑；明暗主题全走查；空状态/错误态齐全；动效（气泡入场、配对成功）到位 |
| **M6** | 打包发布 | 可分发安装 | 2–3d | Android APK（targetSdk 合规、通知权限引导）；Windows 安装包（防火墙引导文案）；测试矩阵走查通过；README 用户手册 |

**合计 ≈ 19–25 人日。** 最大不确定性在 M0（Android 构建链）与 M4（断点续传状态机），两者均已前置。

### 里程碑依赖
```
M0 → M1 → M2 → M3 → M4 → M5 → M6
      └──────────────┘
  M3 与 M4 的 UI 框架可部分并行（气泡卡片样式先行）
```

## 6. 预估风险与问题 ⚠️

| # | 风险 / 预计会遇到的问题 | 概率 | 影响 | 缓解措施 |
|---|------------------------|------|------|---------|
| 1 | **Android 构建链摩擦**：NDK 版本、cargokit gradle 交叉编译、frb android 集成 | 高 | 高 | 放在 M0 第一天验证空包；锁 NDK 版本；失败则降级方案见 TASKS-T0.2 |
| 2 | **路由器 AP 隔离**（访客网络常见）导致互相发现不了 | 高 | 高 | 保留手动输入 `IP:端口` 直连；文档提示"需同一普通 Wi-Fi" |
| 3 | Android 省电模式丢组播包（需 `MulticastLock`） | 中 | 中 | 持有组播锁 + UDP 广播与组播双发 + 3s 心跳 |
| 4 | Windows 首次监听被防火墙静默拦截 | 高 | 中 | 首启引导页提示"允许专用网络"；连接失败有明确文案 |
| 5 | **frb 事件风暴**：传输进度每秒几百次推 UI 卡死 | 中 | 中 | Rust 侧 100ms 合并再推；UI 只重建单个气泡 |
| 6 | Android 切后台/锁屏被系统杀，传输中断 | 高 | 中 | v1 声明"亮屏传输"；前台服务通知保活列为 v1.1（TASKS-T6.x） |
| 7 | **Scoped Storage**：`content://` 路径 Rust 读不到；保存文件要权限 | 高 | 中 | 选文件用 `file_picker`（缓存复制成真实路径）；收件存应用私有目录零权限 |
| 8 | **断点续传状态机复杂**（中途改文件/对端换文件） | 中 | 高 | 文件指纹 = `文件ID+大小+hash前缀`，指纹变即重新开始；状态机独立单测 |
| 9 | TCP 粘包/半包/字节序 bug | 必现 | 中 | 定长帧头 + length 前缀解析器，回环 socket 集成测试覆盖 |
| 10 | 协议演进后新旧版本不兼容 | 中 | 中 | 帧头 version 字段 + HELLO 能力协商，不兼容给升级提示 |
| 11 | 双方时钟不同步 → 消息乱序 | 中 | 低 | 排序用会话内 `seq`，UI 时间用**接收方本地到达时间** |
| 12 | 消息历史膨胀导致列表卡顿 | 中 | 中 | SQLite keyset 分页，首屏只加载最近 50 条，上滑增量 |
| 13 | **frb 版本锁死**（已知：必须 2.8.0，升级要 Dart≥3.9.2） | 中 | 高 | 版本锁定写入 README；升级走独立评估任务，禁止顺手升 |
| 14 | 明文传输可被同网段窃听 / 中间人配对 | 中 | 中 | v1 靠 PIN 限制配对 + "仅在可信网络使用"提示；**v2 上 X25519+AES-GCM**（T6 预留） |
| 15 | 文件名非法字符/编码差异（Win↔Android） | 中 | 低 | UTF-8 规范化 + 非法字符替换 + 重名自动编号 |
| 16 | 大文件 hash/传输导致手机发热掉电 | 中 | 中 | 用 blake3（快）+ 256KB 分块让出 CPU + 前台进度可见 |
| 17 | DHCP/漫游导致 IP 变化、连接断 | 中 | 中 | 断线指数退避重连 + 重新发现自动更新地址簿 |
| 18 | 4GB+ 大文件跨 FAT32 U 盘/目录失败 | 低 | 中 | 文档标注需 NTFS；传输前预检剩余空间 |

## 8. 时间线（单人全职）

```
周1  M0 地基 ── M1 发现
周2  M2 配对 ── M3 文字聊天（核心体验）
周3  M3 收尾 ── M4 文件传输
周4  M4 收尾 ── M5 打磨
周5  M6 打包发布 ── 测试矩阵走查
```

> 风险缓冲：M0/M4 各预留 1 天浮动；若 Android 构建链（风险1）超 2 天未通，立即启用 TASKS 中的降级预案。
